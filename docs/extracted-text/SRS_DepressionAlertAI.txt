1. Introduction

1.1 Purpose

This document specifies the software requirements for DepressionAlert AI, a web-based system that analyzes user-
provided social media text to identify early signs of depression. It defines the functional and non-functional
requirements, use cases, and interface requirements that will guide the design, development, and testing of the
system.

1.2 Scope

DepressionAlert AI allows registered users to submit social media posts, either by pasting text directly or uploading
a CSV file, for analysis using Natural Language Processing and Machine Learning. The system extracts emotional
and linguistic features from the submitted text, computes a depression risk score, and raises alerts when the score
exceeds a defined threshold. Results, trends, and alerts are presented through a web dashboard.
The system provides supportive monitoring and awareness only. It does not perform medical diagnosis or treatment
and all clinical decisions remain the responsibility of qualified mental health professionals.

2. Overall Description

2.1 Product Perspective

DepressionAlert AI is a new, standalone web application. It is not a replacement for clinical assessment tools; rather,
it complements traditional mental health evaluation by providing continuous, text-based monitoring between
clinical visits.

2.2 Operating Environment

OE-1: The system shall operate correctly on current versions of Google Chrome, Mozilla Firefox, and Microsoft
Edge on desktop and mobile browsers.
OE-2: The backend API and machine learning services shall run on a Linux-based server environment with Python
3.11 and Node.js 20.x LTS.

2.3 Design and Implementation Constraints

CO-1: The frontend shall be implemented using React 18.x.
CO-2: The backend API shall be implemented using Node.js, with AI, NLP, and Machine Learning components
implemented in Python 3.11 using scikit-learn and spaCy/NLTK.
CO-3: The machine learning model shall be trained using publicly available, ethically sourced mental health text
datasets.

UC-4: Get Depression Evaluation

Actor(s)               Registered User

Description            A user submits social media text manually or uploads a CSV file so the system can
                       evaluate it for depression-related indicators.

Trigger                User selects Get Depression Evaluation from the Dashboard.

Preconditions          PRE-1. User is authenticated.
                       PRE-2. User has accepted the data-processing consent.
                       PRE-3. The submitted text or CSV file contains user-authorized data.

Postconditions         POST-1. Valid text is stored against the user's account.
                       POST-2. The text is processed using NLP.
                       POST-3. A risk score and risk level are generated.
                       POST-4. The result is stored in the analysis history.

Normal Flow            1. User opens the Depression Evaluation screen.
                       2. User selects Submit Text or Upload CSV File.
                       3. User enters text or selects a CSV file.
                       4. System checks for empty, malformed, invalid, or duplicate records.
                       5. System cleans and processes the valid text using NLP.
                       6. System extracts sentiment and relevant text features.
                       7. Depression Detection Model calculates the risk score.
                       8. System stores and displays the evaluation result.

Exceptions             Submitted text is empty: system asks the user to enter text.
                       Uploaded file is not a valid CSV: system rejects the file and displays an error.
                       Duplicate records are detected: system removes or flags duplicate records.
                       Analysis fails: system displays an error and allows the user to retry.

UC-8: Receive High-Risk Alert and Crisis Support

Actor(s)                 Registered User

Description              The system generates a warning and displays crisis-support resources when the
                         calculated risk score exceeds the configured threshold

Trigger                  Depression Detection Model returns a risk score above the configured high-risk
                         threshold.

                         PRE-2. A valid risk score has been generated.
                         PRE-3. The risk score exceeds the configured threshold.

Postconditions           POST-1. A high-risk alert is created and stored.
                         POST-2. The alert is displayed to the user.
                         POST-3. Crisis-support resources are displayed.
                         POST-4. The alert appears in the user's dashboard and history.

Normal Flow              1. Depression Detection Model generates the risk score.
                         2. System compares the score with the configured threshold.
                         3. System identifies the result as high risk.
                         4. System creates and stores a high-risk alert.
                         5. System displays the alert to the user.
                         6. System displays crisis helplines, support resources, and recommended immediate
                         actions.
                         7. User views or dismisses the alert.

Exceptions               Alert cannot be stored: system logs the failure and retries.
                         Support resources cannot be loaded: system displays the available emergency
                         message and retry option.
                         Alert display fails: system keeps the alert active for the next dashboard visit.

5. Quality Attributes

5.1 Usability

USE-1: Simple Text Submission
The system shall allow an authenticated user to access the Depression Evaluation screen and submit text for
analysis in no more than three interactions from the Dashboard.

USE-2: Clear Dashboard Information
The Dashboard shall display the user's latest risk score, risk level, recent alert status, and behavioural trend
summary without requiring navigation to another page.

USE-3: Input Guidance and Validation
The system shall provide clear labels, instructions, validation messages, and error feedback for manual text
submission and CSV file upload.

USE-4: Responsive Interface
The user interface shall remain usable and readable on desktop computers, laptops, tablets, and smartphones using
modern web browsers.

USE-5: Consistent Navigation
The system shall provide consistent navigation, button placement, terminology, colours, and interface elements
across all screens.

5.2 Performance

PER-1: Text Analysis Response Time
The system shall generate and display a risk score for a valid single-text submission within five seconds under
normal operating conditions.

PER-2: Dashboard Loading Time
At least 95% of Dashboard requests shall load completely within three seconds when accessed through an internet
connection of 10 Mbps or faster under normal load.

PER-3: CSV Processing Feedback
The system shall acknowledge a valid CSV upload within three seconds and display its processing status until the
batch analysis is completed.

PER-4: Concurrent User Support
The system shall support multiple concurrent users without causing significant degradation in response time under
the expected operational load.

5.3 Security and Privacy

SEC-1: Secure Communication
All user credentials, submitted text, uploaded files, analysis results, and alerts shall be encrypted during
transmission using HTTPS with TLS 1.2 or higher.

SEC-2: Consent-Based Processing
The system shall accept and process submitted text only after the user has explicitly granted data-processing
consent. The user shall be able to revoke this consent.

SEC-3: Password Protection
User passwords shall be stored using a secure one-way password-hashing algorithm and shall never be stored or
transmitted as plain text.

SEC-4: Authentication and Authorization
The system shall require authentication before allowing users to submit text, upload CSV files, or access analysis
results, alerts, behavioural trends, and history.

SEC-5: User Data Isolation
The system shall ensure that users can access only their own profile, submissions, analysis results, alerts, and
history.

SEC-6: Secure File Validation
The system shall validate uploaded CSV files for permitted format, file size, malformed content, and potentially
unsafe data before processing.

SEC-7: Session Security
The system shall securely terminate the user session after logout and shall prevent unauthorized access using
expired or invalid authentication tokens.

6. External Interface Requirements

6.1 User Interfaces

The system shall provide a responsive web-based user interface accessible through modern desktop and mobile web
browsers. The interface shall follow a consistent design in terms of colours, typography, navigation, buttons, forms,
and layout.

The system shall include the following main interfaces:

    · Registration and Login Interface: Allows users to create an account and securely log in to the system.

    · Dashboard Interface: Displays the latest depression risk score, risk level, recent alerts, analysis history,

         and behavioural trends.

    · Daily Log / Depression Evaluation Interface: Allows users to manually paste social media text or upload

         a CSV file for analysis.

    · Analysis Result Interface: Displays the generated risk score, risk level, sentiment result, and identified

         emotional or linguistic indicators.

    · Sentiment Alert Interface: Displays a high-risk warning when the calculated risk score exceeds the

         configured threshold.

    · Crisis Support Interface: Provides crisis-support information, emergency contacts, calming exercises, and

6.2 Software Interfaces

The frontend shall be developed using React.js and shall communicate with the Node.js backend through a RESTful API using
JSON-formatted requests and responses.
The backend shall provide interfaces for:

     · User registration and authentication
     · Manual text submission
     · CSV file upload
     · Submission validation
     · Analysis-result retrieval
     · Analysis-history retrieval
     · Behavioral-trend retrieval
     · Alert generation and retrieval
     · Crisis-support resource retrieval
The Node.js backend shall communicate with the internal Python-based NLP and machine-learning service through
a protected service interface.
The Python service shall perform:
     · Text cleaning and preprocessing
     · Tokenization
     · Sentiment analysis
     · Emotional and linguistic feature extraction
     · Behavioral-pattern analysis
     · Depression-risk score generation

     · Risk-level classification
The backend shall store user accounts, text submissions, analysis results, behavioural trends, and alerts in the system
database.

6.3 Hardware Interfaces
The system shall not require any dedicated hardware devices.
Users shall access the system through standard client devices, including:

     · Desktop computers
     · Laptop computers
     · Tablets
     · Smartphones
Each client device shall require:
     · A modern web browser
     · An active internet connection
The server environment shall provide sufficient processing, memory, and storage resources to run the
frontend, backend, database, NLP components, and trained machine-learning model.
6.4 Communications Interfaces
The system shall use HTTPS for all communication between the client application and the backend server.
The frontend and backend shall exchange data through RESTful API requests and responses using JSON.
CSV files shall be transmitted through secure multipart file-upload requests.
Communication between the Node.js backend and the Python-based NLP and machine-learning service
shall occur through a protected internal API.
High-risk alerts shall be delivered through in-application notifications and displayed on the user
dashboard.
All communication containing user information, submitted text, analysis results, or alerts shall be
transmitted through encrypted connections.
