1. WHAT THE PROJECT IS
----------------------
Web-based AI system that detects EARLY SIGNS OF DEPRESSION by analyzing
USER-PROVIDED social-media text via NLP + ML. Registered users paste text or
upload CSV (after explicit consent); the system produces a depression risk
score (0–100) and risk level, stores history, shows trends, and raises a
high-risk alert with crisis-support resources when a threshold is crossed.
Advisory/supportive only — NOT a diagnostic or clinical tool.
Strictly permission-based: nothing is collected automatically.

3. SIX CORE MODULES (SDD §1, §3, §6)
------------------------------------
M1 Data Collection      validateAndStorePost(userId, rawInput, sourceType)
                        - block if consent FALSE ("Consent required")
                        - CSV: parse rows, skip empty/duplicate -> Post(CSV)
                        - manual: reject empty -> Post(Manual)
M2 NLP Processing       preprocessText(post) [Python service]
                        - removeSymbolsAndUrls, lowercase, tokenize,
                          removeStopWords, computeSentiment -> ProcessedText
                        - extractFeatures -> featureVector
M3 Depression Detection computeRiskScore(featureVector, processedTextId)
                        - model.predict_proba -> riskScore = raw*100
                        - >=70 High, >=40 Moderate, else Low
                        - store AnalysisResult(model_version, analyzed_at)
M4 Behavioral Analysis  updateBehavioralPattern(userId, processedText)
                        - rolling averages: firstPersonDensity,
                          absolutistLanguage, negativeEmotionWords
M5 Alert System         evaluateAndGenerateAlert(analysisResult, userId)
                        - if riskLevel == High: create Alert(status=New),
                          notifyUser; else null
M6 Dashboard            aggregated view of results, trends, alerts

4. DATA ENTITIES (SDD §5.1 data dictionary)
-------------------------------------------
User              user_id PK | name | email | password_hash (salted) |
                  consent_given bool | role enum(Standard, Authorized Viewer) |
                  created_at
Post              post_id PK | user_id FK | content text |
                  source enum(Manual, CSV) | submitted_at
ProcessedText     processed_id PK | post_id FK | cleaned_text |
                  tokens array<string> | sentiment_score float(-1..1)
AnalysisResult    analysis_id PK | processed_text_id FK |
                  risk_score float(0-100) |
                  risk_level enum(Low, Moderate, High) |
                  model_version | analyzed_at
BehavioralPattern pattern_id PK | user_id FK | window_start, window_end |
                  firstPersonDensity | absolutistLanguage |
                  negativeEmotionWords   (rolling averages)
Alert             alert_id PK | analysis_result_id FK | created_at |
                  message | status enum(New, Viewed, Dismissed)
Notification      base class -> InAppAlert, EmailAlert(optional) [inheritance]
CSV uploads: held temporarily server-side, discarded once rows persisted as
Post records (SDD §5). All analysis data keyed by user_id (SEC-5).

5. USE CASES (SRS §3)
---------------------
UC-1 Register: name+email+password -> validate -> create -> redirect Login.
   Errors: email exists, missing fields, weak password.
UC-2 Login: email+password -> session -> Dashboard.
   Errors: bad credentials, no account, auth service down.
UC-3 View Dashboard: shows info + options: Get Depression Evaluation,
   View Risk Score, View Analysis History, View Behavioural Trends.
   Errors: load failure (retry), no analysis (prompt evaluation).
UC-4 Get Depression Evaluation: Submit Text or Upload CSV -> validate
   (empty/malformed/invalid/duplicate) -> NLP clean+features -> risk score ->
   store + display. Errors: empty text, invalid CSV, duplicates, analysis
   failure (retry).
UC-5 View Risk Score: latest score + level Low/Medium/High + brief
   explanation. Errors: no result (prompt evaluation), retrieval failure.
UC-6 View Analysis History: records by date — date, risk score, risk level,
   sentiment; selectable detail. Errors: empty state, retrieval failure+retry.
UC-7 View Behavioural Trends: compare current vs previous — changes in risk
   score, sentiment, emotional indicators; charts + summaries. Errors:
   insufficient records (prompt more evaluations), analysis failure.
UC-8 High-Risk Alert + Crisis Support: score > threshold -> store alert ->
   display alert -> display helplines/support resources/recommended actions
   -> user views or dismisses. Errors: store failure (log+retry), resources
   load failure (emergency message + retry), display failure (keep alert
   active for next visit).

7. QUALITY ATTRIBUTES (SRS §5)
------------------------------
USE-1 submit text in <=3 interactions from Dashboard
USE-2 dashboard shows score/level/alert-status/trend summary on one page
USE-3 clear labels, instructions, validation + error feedback
USE-4 responsive: desktop, laptop, tablet, smartphone
USE-5 consistent navigation, buttons, terminology, colours
PER-1 single-text risk score within 5 s
PER-2 95% of dashboard loads < 3 s at >=10 Mbps
PER-3 CSV acknowledged < 3 s + processing status shown
PER-4 concurrent users without significant degradation
SEC-1 HTTPS/TLS 1.2+ for credentials, text, files, results, alerts
SEC-2 consent-based processing; user can revoke consent
SEC-3 one-way salted password hashing; never plaintext
SEC-4 auth required for submit/upload/results/alerts/trends/history
SEC-5 user data isolation (own data only)
SEC-6 CSV validation: format, size, malformed, unsafe content
SEC-7 secure session termination; expired/invalid tokens rejected

9. BACKEND API SURFACE (SRS §6.2)
---------------------------------
Node/Express must provide: user registration + authentication; manual text
submission; CSV file upload; submission validation; analysis-result
retrieval; analysis-history retrieval; behavioral-trend retrieval; alert
generation + retrieval; crisis-support resource retrieval.
Python service performs: text cleaning/preprocessing; tokenization;
sentiment analysis; emotional + linguistic feature extraction;
behavioral-pattern analysis; risk-score generation; risk-level
classification. Communication = protected internal API.

10. PROCESS FLOW (SDD §3.2 / DFD)
---------------------------------
User (consent) -> submit (paste|CSV) -> validate+store Post (D1) ->
preprocess -> ProcessedText (D2) -> classify -> AnalysisResult (D3) ->
update BehavioralPattern (D4) -> threshold? -> Alert (D5) + notify ->
Dashboard aggregates D3+D4+D5 -> user.
Data stores D1..D5 = Post, ProcessedText, AnalysisResult,
BehavioralPattern, Alert.

11. RISK THRESHOLDS (SDD §6.3)
------------------------------
risk_score = predict_proba * 100 ; >=70 High (triggers alert), >=40
Moderate, else Low. SRS UC-5 labels bands Low/Medium/High.
